# 设计说明：为什么长这样

本文记录实现层的取舍，供后续改动与 review 对照。范围只到 P1 + P2。

## 1. 只有两条真正的「轴」

原方案设想三轴坐标（时间 / 主题 / 情绪），并用 Morton 码把三维压成一维键值。落地时放弃了：

- 时间是**有序区间**，B-tree 的 `(ts)` 范围扫描已经是最优路径，Z-order 只会多一层不可调的复杂度。
- 显著度是**枚举分档**（hot / warm / cold），`WHERE salience=?` 足够。
- 主题 id 是**分类标签，不是度量空间**：`topic_id=3` 与 `topic_id=4` 不相邻，折叠进高位比特后前缀扫出来的「盒子」没有语义意义。

结论：**时间线是结构，语义网是结构，显著度是权重**。三者不构成可做空间索引的坐标系。所谓「立体」只作为对外表述，工程上不承诺三维查询。

因此存储是「链表 + 邻接表 + 三层枚举」，检索是「时间区间 + 关键词 + 图限制跳数」。

## 2. 链表不变量（最容易写坏的部分）

锚点链的唯一真相源是 `meta.head` / `meta.tail` 与每个节点的 `prev_id/next_id`。维护规则：

- **追加**：取 `tail`，新节点 `prev_id=tail`，`tail.next_id=新节点`，更新 `tail`；若 `head` 为空同步设 `head`。
- **删除**：`prev.next = next`、`next.prev = prev`；删的是头就改 `head`，删的是尾就改 `tail`。
- 两个操作都在**单事务**内完成，任何一步失败整体回滚。
- `chain_integrity()` 做三向校验：每个节点的指针互指、head 无 prev、tail 无 next。它是验收测试的判定依据。

这套规则的价值在于：删除 20 个随机锚点后，时间线仍能从 head 走到 tail，不会出现「指针指向已删除节点」的静默损坏。

## 3. 为什么写入路径不用模型

- 每轮对话都要判断一次，模型调用会让成本随对话轮数线性上升。
- 规则打分可解释、可回归测试，阈值可配置；模型打分在阈值附近不稳定。
- 代价是召回率有上限：隐喻、反讽、跨句指代会被漏判。当前接受这个代价，用 `remember` 入口兜底显式写入。

## 4. 为什么摘要不做二次改写

规则截断（优先在句号处切）能保证「用户原话可追溯」。一旦引入改写，锚点摘要与原始发言之间就出现不可核对的信息，与「稀疏骨架、细节靠原文补」的设计冲突。

## 5. 召回预算的裁剪顺序

`retrieval.recall()` 拼装顺序固定为：工作记忆 → 语义 → 锚点。裁剪时按行丢弃，先丢尾部（锚点），保留工作记忆——当前对话的连贯性优先于历史细节。字符预算和估算 token 预算同时生效，都是硬上限；一旦当前行放不下就停止，不再跳过它去捡后面更短的低权重行。锚点排序按「搜索顺序近似相关度 × 近因 × score × recall_count」加权，固定条目不参与近因衰减；token 估算按 CJK 一字一 token、ASCII 词/数字串一 token，不引入模型分词器，因此是保守近似而不是精确计数。

## 5.1 假设区与置信度边界

- 召回只返回 `active` 且带原话的条目；`hypothesis` 状态只保留原话供面板核对，不建语义、不参与召回。
- 假设识别只在句首命中「假设/假如/倘若/假装/角色扮演/what if/假如 + 第一人称」，或出现「如果/要是 + 你当/你扮演/你变成」时降级到假设区；「如果」「要是」「设定」「测试一下」单独出现不再命中，显式「记住/别忘/记得」优先。句首条件前已有事实/偏好（如「我对花生过敏，如果…」）时不判假设，避免语义被丢。假设句去掉固定 +0.35 的假设加分后仍要过 `anchor_threshold` 才落库，假设区上限 200 条，寿命按 `created_at` 而不是模型可传的 `ts` 计算；淘汰时事务内只删行，提交后再统一收尾 WAL/FTS。
- 返回块用 `[时间｜salience｜摘要]` 与 `（用户原话：…）` 分开标注，摘要只来自用户原句、不拼助手回复；头部要求「没记录就说不记得」，把摘要/推断/原话在提示层显式隔离。

## 6. 三个可量化的风险

1. **hot 自我强化**：`recall` 会让 `recall_count++`，热点越召回越 hot。当前靠 `last_recalled` 时间窗缓解，长期仍需要「半衰期衰减」。P2 内先观察，不在本版实现。
2. **语义网变稠**：共享标签的 Jaccard 建边会让高频词（如「配置」）连成一片，2 跳扩展容易召回无关条目。缓解手段是标签上限 6 个 + 扩展上限 12 条；真正的解法是定期合并孤立节点（P3）。
3. **跨时期混叠**：语义索引不带时间，容易把两个时期的事混成一件。缓解是 `attach_anchor_id` 回标时间，并在渲染时保留锚点时间标签。

## 7. 验收与当前状态

| 验收项 | 判定方式 | 状态 |
|---|---|---|
| 锚点产出率 | 100 轮日常对话 → 3–8 个锚点 | 通过（`tests/test_acceptance.py`） |
| 链完整性 | 随机删 20 个节点后 `chain_integrity()` 无 problem | 通过 |
| 注入体积 | 50 查询 P95 ≤ 全量基线 35% | 仅 v0.1 历史口径；v0.4 已取消被动注入 |

未达标时的调整顺序：先调 `anchor_threshold`，再调 `working_window`，最后才动打分权重——阈值是唯一不需要改代码的旋钮。

## 7.1 v0.1 历史：为什么曾经两条腿

> v0.4 已取消被动注入。本节保留为历史取舍记录，不再是当前行为。

只靠入口，召回率取决于猫娘是否主动想起来调；把 `prompt_block` 翻身交给「模型自觉」，实际触发会很低。只靠被动注入，则每条都要付注入成本，且无法应对需要深挖的追问。

最终分工：

- **主动**：`recall` 入口 + `recall_temporal_memory` LLM 工具，模型按「聊到过去时」的描述自行调用。
- **被动**：`observe` 之后插件侧判断命中，用 `push_message(ai_behavior="read", visibility=[])` 把 300–500 字的精简块送进下一轮。

v0.4 删除被动一侧的原因：用户明确要求「取消原版的注入方式」，且证据记忆的生命周期（休眠、冲突、固定）比自动推送更重要。

## 8. 明确不做的事（本版）

- 体素、Morton/Z-order、空间查询。
- L2/L3 摘要金字塔（分层巩固）。
- 前瞻记忆（到期提醒）。
- 回忆重构（召回时改写摘要）。
- 自动挂 `@message` 钩子：钩子契约未在本机验证，先保留显式 `observe` 入口，避免静默失败。

## 9. 已拍板

- **存储**：插件私有 sqlite，按角色分库为 `memory-<角色>-<sha256前8位>.db`（无角色名时 `memory.db`）。要 FTS5、显式事务和链表修复，就别挤宿主库。
- **自动钩子**：不挂 `@message` 自动 `observe`。本体已有 `memory_server` 在写，自动 observe 会重复记、重复注入。写入仍走显式入口。
- **许可**：MIT。
- **注入**：v0.4 取消被动注入，只保留模型按需调用 `recall_temporal_memory` 的拉取路径；见 §11。

## 11. v0.4：证据记忆与取消注入

### 11.1 为什么回滚原版

原版（0.1.0）已有锚点链、语义网、FTS5、热温冷和按角色分库；v0.3 只读版把这些入口全删了。用户要求「退回原版，再改写注入方式」，因此 v0.4 以 0.1.0 为基线恢复完整结构，而不是在只读版上继续删。

### 11.2 取消 `push_message`

`injection.py` 与 `_push_read` 物理删除，插件里不再有 `push_message` 调用、`inject_enabled` 配置和 `injections` 台账。原版的「每轮悄悄喂一段」变成「模型显式调用才拉取」：

- `recall_temporal_memory` 是唯一模型可用的读取路径；
- `recall` / `timeline` 入口加 `metadata={'agent_hidden': True}`，只服务设置页；
- `observe` 返回值不再含 `injection`。

### 11.3 证据字段

`anchors` 与 `semantics` 都增加：

- `quote`：用户原句，最多 1200 字；老库迁移时回填 `summary`。
- `source_event_id` / `source_kind`：来源事件 id 与来源类型（chat_turn / manual）。
- `kind`：event / preference / decision / fact。
- `status`：active / dormant / pending / archived。
- `score`、`confirm_count`、`last_confirmed_at`、`updated_at`。
- `conflict_group`：待确认冲突组。

召回时先过滤 `status='active'` 且 `quote` 非空，避免「摘要还在、证据没了」的条目继续进入模型。渲染 `prompt_block` 时摘要后附 80 字原话摘录，让模型看到的是可核对证据而不是二手概括。

### 11.4 休眠

`MemoryStore.lifecycle()` 每小时由插件定时器调用：

- 事件：`last_confirmed_at` 超过 `dormancy_event_days`（90）→ dormant；
- 偏好/事实/决定：超过 `dormancy_preference_days`（180）→ dormant；
- `pinned=1` 一律跳过。

「确认」有三条来源：面板「确认有效」、同一条偏好再次出现时自动 reconfirm、`remember` 写入时刷新。召回本身不刷新确认时间，避免「看过就算确认」把休眠机制架空。

### 11.5 矛盾

规则判定只覆盖可解释的场景：

- 偏好：谓词对象相似 ≥0.5 且极性相反；
- 偏好复认：对象相似 ≥0.6 且极性相同，刷新旧条而不重复建条；
- 事实：同一主语模板（`我住在…`、`我叫…`、`我的…是…` 等）且内容不同；
- 决定：同一前缀（决定/计划/打算/准备/约好）且目标不同、相似度 ≥0.35；
- 通用兜底：相似度 ≥0.65 且否定词相反。

命中后 `materialize_conflict()` 同时把旧条和新条置为 `pending`，共享 `conflict_group`；`resolve_conflict()` 只保留一条 active，其余 archived。

### 11.6 纠正与撤销

`revisions` 表保存 `before_json / after_json`。面板的纠正、固定/取消、移除、冲突处理都写一条 revision；`undo_last()` 恢复最近一条未撤销的快照。动作跨角色库时，插件先比较各库的 revision 时间，只撤销最新那一个，不批量回滚。`quote` 是证据原文，纠正白名单不含它；摘要/内容、类型和标签可以改。标签改动会重建 FTS 与语义邻接边。

### 11.7 手动保留

`pinned=1` 时：

- 不参与生命周期休眠；
- `effective_score` 恒为 1.0，不随 `last_confirmed_at` 衰减；
- 面板显示「已固定，不衰减」，剩余休眠天数显示为空。

### 11.8 仍然不做

- 不用模型做摘要/抽取：写入路径仍零模型调用，避免延迟与隐私问题。
- 不做自动 `@message` 钩子：覆盖率和重复写入仍未验证。
- 不做冲突的自动裁决：必须由用户在面板选一条。

# 时序记忆 · 用户指南

这个插件保存的不是完整聊天记录，而是**可以回查原话的证据记忆**：值得记住的事件、偏好、决定和事实，以及每条对应的用户原句与时间。

## 它记住什么

- **事件锚点**：一句摘要 + 用户原话 + 时间标签 + 分数 + 标签。
- **偏好/事实/决定**：从原话里切出的陈述句，带原话证据、来源、确认时间和状态。
- **工作记忆**：最近 8 行原文（用户、助手各一行，约 4 轮对话），只在本插件私有库里滚动覆盖。

闲聊、寒暄、「嗯 / 好」不会占时间线；大部分日常对话只进工作记忆。

## 它怎么决定记不记

五类信号累加超过阈值（默认 0.3）就留一个事件锚点：

- 「记住 / 别忘 / 很重要」→ 直接记，并标记 hot
- 情绪波动明显（焦虑、崩溃、特别开心）→ 记
- 第一次配置、遇到报错、学到新知识 → 记
- 做了决定、定了计划、有截止时间 → 记
- 让我帮忙排查、提交、处理 → 视上下文记

偏好和事实片段不受锚点阈值限制：即使这句话整体分数不够，也会单独留一条可核对的原话证据。

## 它怎么回忆

只有一条路：**按需拉取**。

- 你说「上次那个报错是什么」「之前配 DSH 时我说过什么」，猫娘才会调用召回工具。
- 插件不会在每轮对话后偷偷往上下文里塞内容；原版的 `push_message` 被动注入已经删除。
- 召回只拿 `active`、带原话证据的条目，按下面的顺序取，默认封顶 1200 字符：
  1. 工作记忆：最近 8 行原文，保证当前话题不断片。
  2. 偏好/事实：关键词命中后，沿语义网最多走 2 跳。
  3. 时间线锚点：命中后带前后各一条，还原当时场景。

## 到期休眠与手动保留

- **事件**：90 天没有再次确认，自动休眠。
- **偏好 / 事实 / 决定**：180 天没有再次确认，自动休眠。
- **手动固定**：在面板点「手动保留」，条目不参与自动休眠，分数恒为 1.0，不随时间衰减。
- 同一偏好在对话里再次出现，会自动刷新确认时间，不会重复建条。
- 休眠不是删除：原话和来源都还在，面板可随时「确认有效」唤醒；也可导出后自行处理。

## 矛盾怎么处理

如果新说法和旧说法冲突：

- 偏好同对象、语气相反，例如「我喜欢猫」vs「我不喜欢猫」或「我讨厌猫」；
- 事实同一主语模板但内容不同，例如「我住在上海」vs「我住在北京」；
- 决定同一前缀但目标不同，例如「决定去北京」vs「决定去上海」；
- 或高度相似但一个带否定、一个不带。

插件不会偷偷覆盖旧条，而是把两条都标成**待确认**，暂停召回。面板顶部会出现冲突组，选一条「采用这条」，另一条归档；选错可以撤销。

没有冲突组的待确认条目（例如异常中断或旧版本遗留）会出现在面板「未分组待确认」区，可以逐条「保留这条」转为有效，或「归档这条」移出召回。这些条目在没处理前会占用容量但不会正常召回。

## 设置面板

- **记忆列表**：类型、状态、分数、角色、剩余休眠天数。
- **看原话**：展开 `quote`、来源类型、宿主事件 id；没有原话的条目不会进入召回。
- **确认有效**：刷新确认时间，唤醒休眠条目。
- **手动保留**：固定后不衰减；再点一次取消。
- **纠正**：改摘要/内容、类型（事件/偏好/决定/事实）、标签；原话证据只读，避免证据被改写。
- **移除**：从召回中移除并立刻释放写入名额，但保留原话与撤销记录。
- **撤销上一步**：只撤销最近一次面板动作；不会连带回滚别的角色库，撤销快照最多保留最近 1000 条。
- **清理旧记忆**：永久删除所有已加载角色库中已移除超过 30 天或距最后一次确认超过 365 天且未固定的条目，释放容量名额；不可撤销，建议先导出 JSON。
- **永久删除这条**：单条立即物理删除，连带清掉关联和撤销快照，不必等 30 天清理；每点一次都要确认，删除后不可撤销。删完如果工作记忆里还留着同一句原话，会再问一次「要不要一起删」，不选就原样保留。已移除条目在“已移除的记忆”区单独列出，最多最近 120 条，也能直接永久删除。sqlite 开了 `secure_delete`，删掉的字节会被零覆盖，所以单条删除不需要再 VACUUM 收尾。
- **清空全部记忆**：两次确认后清空数据目录里的 `memory.db` 和全部 `memory-*.db`，包括当前没加载的角色库，并一并删掉迁移留下的 `*.migrated` 旧库备份；清空后执行 `wal_checkpoint(TRUNCATE)` + `VACUUM` 回收文件，返回实际清空的库数与失败数。
- **总开关**：关闭后写入和召回一起停用；模型侧召回返回空结果并标记 `disabled`，面板预览直接报“总开关已关闭”，已有记忆仍可查看和删除。
- **工作记忆**：展示每个角色最近 8 行用户/助手原文（8 行≈4 轮），每条可单独永久删除；和记忆一样是明文 sqlite，也会出现在导出 JSON 的 `working_memory` 里。
- **未加载的角色库**：磁盘上存在但没挂载的库会单独列出角色名、锚点/偏好条数、待确认数、工作记忆行数和最后写入时间，只是只读快照（最多 30 秒延迟，不会改文件）。要处理里面的条目点「载入这个库」，插件才把它挂到当前列表；启动时仍然不会全量挂载所有角色库。
- **待确认提醒**：状态栏会显示待确认条数，其中有条目已经等了超过 7 天时会额外提醒（含最早一条等了多久），避免待确认一直挂着两边都不召回。
- **导出 JSON**：含 anchors、semantics 与最近 8 行 working_memory 的全部字段和原话；未加载的角色库也会临时打开、读完就关一起导出，打不开的库会计入 `failed_databases` 并在提示里列出。单表最多导出 10000 条、所有角色库合计最多 20000 条，超出时返回 `truncated` 标记和提示，不会静默丢数据。
- **写入与生命周期**：总开关、工作记忆行数（8 行≈4 轮）、建锚点阈值、摘要上限、hot/cold 参数、事件/偏好休眠天数、召回预算。
- **原话核对**：`observe` 摘出来的每句证据必须能在这一轮 `user_text` 里找到；`remember` 会拿最近工作记忆里的用户发言比对。对不上就放进「未分组待确认」并标 `quote_verified=false`，核对后点「保留这条」才进召回；工作记忆为空时无从比对，维持原行为。
- **界面语言**：面板所有文案走 `i18n/`，跟随宿主 locale 显示（`zh-CN` / `en` 各 192 个键），不在代码里写死中文。
- **单个库坏了不影响别的库**：启动和每小时维护都逐库 try/except，坏库只记一条警告（插件日志）并跳过，其他库照常维护；启动不会因此失败，库修好后下一次维护会自动清掉错误记录。
- **已知限制**：召回只增加召回计数，不刷新「最后确认时间」，休眠倒计时只认确认和纠正；启动时只挂载老 `memory.db` 或已写入 owner 的角色库，纯角色库要等首次调用才加载（面板有只读列表可手动载入，但「清理旧记忆」仍只覆盖已加载库）；原话核对只能保证插件内部自洽，调用方整体伪造原话挡不住；工作记忆只有 8 行，删除记忆条时能提示到的也只有还在这 8 行里的原话。

## 数据与隐私

- 数据落在插件私有目录，按角色分库为 `memory-<角色>-<sha256前8位>.db`；取不到角色名时沿用唯一已有的角色库，没有才用 `memory.db`（sqlite）。0.4.9 的旧角色库会在首次访问时自动迁移。
- 每个角色库最多 5000 条有效/待确认记忆；已移除和已休眠的条目不计入名额，可在面板「清理旧记忆」永久删除。
- 不调用模型做摘要或抽取，全部是本地规则；不会把原话发给第三方。
- 对话原文与摘录以**明文**保存在插件私有 sqlite（`data/`），导出 JSON 同样是明文；插件不做加密，也不上传。原话证据由调用方（模型）传入，插件只做「这句是否出现在本轮/工作记忆里」的自洽核对，宿主没有逐字核实聊天记录。
- 不调用 `push_message`，不往对话写消息，也不写宿主记忆。
- 卸载插件时插件数据目录会一起删除；想手动清空，停止插件后删除对应 `memory-*.db` 即可。
- 老库升级会自动补 `quote / status / kind` 等列，并把 `summary` 回填为证据，不删数据。

## 已知限制

- 自动写入依赖每轮调用 `observe`（宿主或上层 agent 触发），插件本身不挂 `@message` 钩子，覆盖率不保证。
- 面板每次读取单库最多 300 条、显示 240 条；固定条目优先，其次 active，再按时间。单库固定条目超过 300 条时，更早的固定条目要取消固定或处理掉一部分后才会出现。
- 矛盾判定是保守规则，只覆盖偏好极性、事实主语模板和高相似否定反转；复杂语义冲突仍可能漏判，需要面板人工纠正。
- 摘要由规则截断，长句会丢后半段；原话证据保留全文，但面板里也只展示截断前的 1200 字。
- 中文检索依赖 FTS5 trigram；若宿主 sqlite 版本过低会自动回落 `LIKE`，召回会变粗。
- 升级后若 `memory.db` 与角色库同时存在，启动只挂角色库并跳过老库，避免统计重复；老库会留在目录里。
- 只读快照打开 WAL 库时会留下 sqlite 自己的 `-wal` / `-shm` 附属文件，这是读取行为，不影响数据；下次载入该库时会被正常接管。
- 暂不支持前瞻记忆（待办到期提醒）与回忆重构（每次回忆轻微改写摘要）。
